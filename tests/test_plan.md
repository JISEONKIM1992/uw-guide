# 지원 Agent 테스트 계획

## 1. 업로드 테스트
- 가이드라인 `xlsx/csv` 업로드 시 요약이 생성되는지 확인
- RD 원본 `xlsx/csv` 업로드 시 메타와 요약이 갱신되는지 확인
- 업로드 삭제 후 요약과 payload가 같이 초기화되는지 확인

## 2. 변환 테스트
- 변환 후 `시스템반영_RD.xlsx` 다운로드가 가능한지 확인
- `Sheet1`이 변경 전/후 기준으로 바뀌는지 확인
- 변경이 없는 특약은 히스토리/수정필요항목에서 제외되는지 확인

## 3. 상품 목록 테스트
- 상품명 기준으로 중복이 제거되는지 확인
- 저장 전 `pendingProducts`가 질문에 반영되는지 확인
- 상태값이 `미착수 / 진행중 / 보류 / 완료`만 표시되는지 확인

## 4. OpenAI 질의 테스트
- `암진단특약` 질문 시 `LI00112` item이 우선 선택되는지 확인
- `신입원특약` 질문 시 해당 특약 item이 선택되는지 확인
- `인별합산`이 최종 한도로 오해되지 않는지 확인
- payload 미리보기에서 `comparisonSummary`와 `reference.individualSum`이 분리되는지 확인

## 5. 오류 테스트
- 프록시 미실행 상태에서 실패 메시지가 명확한지 확인
- API 키가 잘못된 경우 프록시가 즉시 거절하는지 확인
- 헤더 구조가 조금 바뀐 파일에서도 최소한의 요약이 가능한지 확인

## 6. 수동 검토 포인트
- 일반/간편 단일건이 다른 경우 룰검토로 가는지
- 일반/간편 단일건이 같은 경우 자동반영으로 보이는지
- 특약명과 보험코드가 혼동되지 않는지

## 7. 추가 테스트케이스

### TC-07 암진단 자동반영
- 대상 특약: `암진단` / `LI00112`
- 입력 기준: 가이드라인 `as-is 2000`, `to-be 3000`, RD판 `가입한도금액RD 2000~2000`
- 기대 결과:
  - `Sheet1`의 해당 행이 `3000~3000`으로 갱신된다.
  - `가입금액단위RD`는 기존 `1000`을 유지한다.
  - `인별합산 5000`은 참고값으로만 남고, 최종 한도 판단에는 쓰이지 않는다.
  - 변경히스토리 / 수정필요항목 / 1장요약에 암진단 변경건이 1건만 남는다.

### TC-08 신입원특약 룰검토 분기
- 대상 특약: `신입원특약` / `LI00120`
- 입력 기준: 가이드라인 `일반/건강 3000 -> 3000`, `간편 3000 -> 4000`, RD판 `가입한도금액RD 3000~3000`
- 기대 결과:
  - 일반/건강과 간편 한도가 서로 다르므로 자동수정이 아니라 `룰검토 필요`로 분기한다.
  - RD판의 수치가 즉시 변경되지 않고, 검토 가이드 문구가 함께 표시된다.
  - 변경히스토리에는 실제 변동이 확인된 항목만 쌓이고, 변경 없는 설명성 항목은 제외된다.

### TC-09 입원간병인 룰형 값 유지
- 대상 특약: `입원간병인` / `LI00121`
- 입력 기준: RD판 `가입한도금액RD`가 `#SPE7Q3211` 같은 룰형 값으로 저장됨
- 기대 결과:
  - 룰형 값은 숫자로 강제 변환하지 않고 검토 대상으로 표기한다.
  - 가이드라인 숫자값이 있더라도, 룰형 값이 있으면 자동수정보다 해석 확인을 우선한다.
  - `계약금액확인내용RD` 등 룰 관련 필드는 유지하고, 변경 가능한 숫자 필드만 별도로 판단한다.
